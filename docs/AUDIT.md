## 业务、数据库与缓存

真实 schema 见 [DATABASE_SCHEMA_ACTUAL](DATABASE_SCHEMA_ACTUAL.md)，与 [DATABASE_DESIGN](DATABASE_DESIGN.md) 对照为10张 InnoDB 表。金额均为 DECIMAL/BigDecimal；用户名、订单号、用户请求键及购物车组合有唯一约束。多态商品由Service检查，历史订单保存快照。created_at只在user、employee、orders，当前无updated_at和软删除；这些限制已记录，没有擅自迁移历史表或为了AI凑表。

首次检查新库10表均为空。授权演示脚本已真实执行并再次执行验证数量不增长：1用户、1员工、4分类、12菜、10口味组、4套餐、12组成、3订单、4明细；密码存 BCrypt12。脚本仅 INSERT 缺失数据，不覆盖同名账号密码；按名称匹配菜单，适用空库/专用演示数据，不保证任意重名菜单或并发导入安全。验收随机账号与其订单已按精确用户名清理，演示数据保留。

| 模块 | 真实验证与约束 |
| --- | --- |
| 认证 | 注册、登录、错误密码、不存在账号、有效/非法/篡改/过期Token、角色拒绝；密码非明文；客户端退出清理 |
| 分类 | 增改删、类型不可变、启禁用、分页、用户只见启用；有引用时删除冲突 |
| 菜品 | 增改删、上下架、分类与分页、口味同事务；下架后才可删，套餐引用保护；图片URL/价格验证 |
| 套餐 | 增改删、上下架、分页、组成同事务；任何组成菜品/分类停售，套餐在用户端不可售且结算拒绝，后台保留状态 |
| 购物车 | 加菜/套餐、重复合并、减量/删除/清空、按用户隔离；读写均来自服务端身份 |
| 订单 | 真实SQL核价、幂等、历史/详情、取消/再下单、受控状态机；完成不能回退；明细故障完整回滚 |
| Redis | 真实Miss→数据库→缓存→Hit，命中时不访问Mapper；商品修改提交后失效。分类10分钟、热点菜品120秒，禁null但可缓存空结果 |

当前没有店铺营业状态模型/接口，因此没有店铺状态缓存。没有为面试加入分布式锁、随机TTL或复杂防穿透组件；现有小规模单实例证据不足以证明它们必要。失效故障/并发回填仍可导致TTL内陈旧菜单，结算绕过缓存读数据库，不声称强一致。

覆盖层级补充：后台分类/菜品/套餐完整CRUD主要通过Service与真实MySQL集成测试，分类另有MockMvc API验证；10组独立HTTP未逐个执行全部后台菜单CRUD。套餐未使用缓存；套餐组成事务经代码及正常CRUD检查，未专门注入第二条组成失败。真实失败回滚证据针对订单创建和菜品创建，不扩大为每个写接口都做过故障注入。

## AI真实边界

用户7个工具、管理员3个工具均只读，全部调用Service；没有任意SQL、自动加购、下单、支付或取消工具。私有工具身份由JWT/UserContext/后端ToolContext传递，模型schema不能选择userId；管理员Service再次验角色。A/B越权在真实数据库检查。注入测试证明消息层级、工具白名单、确定性权限，不证明真实LLM不会幻觉或忽略提示。

Memory按(userId, conversationId)隔离、20条窗口、1000会话、30分钟闲置淘汰；同会话并发拒绝，失败不存半截回答。测试检查“辣”的历史进入“30块以内”的下一次Prompt；Mock本身不理解偏好，重启不保留历史。

Structured Output只接受reason/dishIds草案，Java校验候选、去重、可售状态并按数据库BigDecimal重算；预算80的浏览器结果为72。预算不明确则要求明确输入。价格可信不等于真实模型已理解人数、辣度或过敏要求。

RAG五份知识为教学示例，400字符/80重叠，2048维本地字符哈希Embedding，SimpleVectorStore Top-3、阈值0.10。四问命中配送/优惠券/退款/食品安全各自文档，答案显示来源；这是真实本地词法检索，不是神经语义Embedding或真实商家承诺。管理员统计由固定SQL计算，仅当前已完成订单计入金额，套餐不拆分为单品销量，金额不等于实收。

Provider支持环境变量AI_BASE_URL、AI_API_KEY、AI_MODEL，默认DeepSeek兼容路径。没有调用真实供应商。**等待API Key进行真实验证。** 后续先“你好”单轮，再测试真实工具选择、多轮偏好、结构化输出、RAG总结、管理员分析和流式。45秒后不再启动新工具不等于同步链路严格总超时；SSE另有45秒总超时。没有真实额度耗尽响应的供应商证据，受控失败模型/HTTP500只能证明应用降级。
